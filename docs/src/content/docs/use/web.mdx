Every display has its own web page. Open its address in a browser on the same network:

```text
https://192.168.1.50/
```

The plain `http://` address sends the browser on to it.

<Image src={overview} alt="The Overview page: a live picture of the screen beside the device's status" class="screen-wide" />

## Signing in

The page asks for the **admin password**. The display makes one up the first time it starts.
Find it on the display under **Settings → Network & internet → Web access**, along with the address.
Tap the eye to show it, or type a new one there. The same password is the **Admin password**
(`frontend_password`) entity in Home Assistant, hidden until you reveal it.

A sign-in lasts 30 days and renews itself while you use the page. Changing the password signs every
browser out. After five wrong passwords in ten minutes, the page stops accepting tries from that
browser's address for a while.

Scripts sign in too; see [the API](#api).

## The certificate

Out of the box the display uses a certificate it made itself, so the browser warns that the
connection isn't private the first time. Accept it once and the warning stays away for that browser.

To get rid of the warning, give the display a real certificate from
[Cert Warden](https://www.certwarden.com/). Set these on the **Network & internet** page in the
browser, or in Home Assistant:

| Setting | What it is | Entity |
|---|---|---|
| Cert Warden server | Cert Warden's address, like `https://certs.example.com`. A bare host name means `https://` | `text.<device>_frontend_cert_warden_server` |
| Certificate name | The certificate's name in Cert Warden | `text.<device>_frontend_cert_warden_certificate_name` |
| Certificate API key | The certificate's API key | `text.<device>_frontend_cert_warden_certificate_api_key` |
| Key API key | The private key's API key | `text.<device>_frontend_cert_warden_key_api_key` |

The **Certificate** sensor (`certificate_status`), also shown on **Web access**, says how it went:
**Self-signed**, **Fetching**, the certificate's name and expiry date, **Wrong API key**, **Can't
reach Cert Warden** or **Expired**.

## Settings

### Changing settings

The sidebar has the same pages as the Settings menu on the screen, with the same names; open one to
jump between its sections. Passwords, PINs and keys stay hidden until you tap the eye, and empty
text fields show an example of what goes in them. Switches and lists save as soon as you change
them; text saves when you press <kbd>Enter</kbd> or leave the field.

**Search** (<kbd>⌘</kbd> <kbd>K</kbd>, or <kbd>Ctrl</kbd> <kbd>K</kbd>) finds any setting by name.

<Image src={search} alt="Search finding the Volume buttons setting" class="screen-wide" />

The pulse button at the top opens **Events**: settings and readings as they change, newest first.
The screen button picks **Light**, **Dark** or **Auto**, which follows the computer.

## Overview

The display's name and model, with what it's doing: whether the microphone is muted and the
camera covered, the light in the room, the call in progress, what's playing, the temperature and how
long it has been running. Each line appears when the display has it. Until Home Assistant has
adopted the display, an **Add to Home Assistant** button opens Home Assistant's ESPHome setup.

Beside them is the screen as it looks right now, refreshed every three seconds while the page is
open.

### Screen control

On screened devices, choose **Take control** over the preview to start live video and input.
Click or tap to press, and drag to swipe. On a computer, open a text field on the remote screen
and type with your keyboard; there is no separate typing box. Click the remote screen again if
typing stops reaching it.

**Fullscreen** uses the whole browser viewport, with controls over the picture. **Exit fullscreen**
or <kbd>Esc</kbd> leaves fullscreen; **Release control** returns to the preview. Only one remote
controller can connect at a time. Two minutes without input, or switching away from the browser
tab, returns to the preview and stops video. Choose **Take control** again to resume.

Remote control works only on the local network and does not send audio. Live video starts only
after **Take control**; opening the page or scanning a pairing code does not start it.

### Control from another device

Choose **Control on another device** and scan the QR code with a phone or another computer on
the same network. It opens a screen-control page without asking for the admin password. Choose
**Take control** there to connect; release any existing controller first.

The code can be scanned more than once during its two-minute lifetime. **Refresh code** replaces
it and invalidates the old code. Each paired browser gets its own 15-minute session; the QR code
expiring does not end a session already paired. Pair again when the page reports that access has
expired or been revoked. For a connection failure, check the network and use the page's retry button.

Pairing grants access to the screen and its input, not the admin settings or other admin APIs.
Keep the QR code private. The link uses the address currently open in your browser; that address
must also be reachable from the device scanning it. See [Signing in](#signing-in) if its browser
shows a certificate warning.

For typing into just one field with a phone's keyboard, use the
[QR button on the on-screen keyboard](/use/settings/#typing-with-a-phone) instead.

## Call

**From this browser** calls the display, with audio or video, using the computer's microphone and
camera. The browser asks for them the first time. **From** the display lists the other devices
in this home: call any of them from the display, as if you'd tapped it in
[Intercom](/features/intercom/). Answer, mute and hang up from the same page.

<Image src={call} alt="The Call page: call the device from this browser, or call another device from it" class="screen-wide" />

A call from the browser shows up on the display as **API**. It's answered automatically only with
**Auto-answer** on, and, when **Answer from** is **Selected**, **Auto-answer API calls**
(`call_answer_api`) on as well.

## Broadcast

Tap the button, talk, and tap it again to send, up to 30 seconds. The message plays on this
display and on every other device in this home, like a
[broadcast](/features/intercom/#broadcasts) said to the assistant. **Record on** the display
**instead** has you speak to the display after its tone; it sends when you stop talking.

<Image src={broadcast} alt="The Broadcast page: a button to hold and talk" class="screen-wide" />

## Developer

- **Log** and **Diagnostics** download the display's log and a JSON file of every entity with its
  current value. Attach both to a bug report; check them for anything you'd rather not share first.
- **Export settings** downloads portable settings as JSON, including dashboard mode and
  the other settings available to Fleet sync. Store the file privately: it may contain passwords
  and credentials. Device-local settings are excluded; this is not a complete device backup.
- **Import settings** opens a settings JSON file. Confirm the number of settings to apply; matching
  settings are overwritten and settings absent from the file stay unchanged. The result lists how
  many changed, skipped settings, and any errors. Unsupported and device-local settings are skipped.
- **Run** calls any of the display's actions, the same ones Home Assistant has: pick or type one,
  fill in its fields, and run it. An action that answers shows the answer below.
- **Readings** lists every sensor with its current value. Type in **Filter** to find one.

## API

Everything the page does goes through `/api/v1/` on the same address, so a script can do it too.
Sign in one of two ways:

- **Basic authentication** on every request, with the admin password. The username is ignored.
- **A token**: `POST /api/v1/login` with `{"password": "…"}` answers `{"token": "…"}`. Send it as
  `Authorization: Bearer …`. It lasts 30 days. Changing the admin password ends every token.

Wrong passwords count toward the same [lockout](#signing-in) as the page. Add `-k` to `curl` while
the display has its own [certificate](#the-certificate).

| Request | Does |
|---|---|
| `GET /api/v1/device` | Name, model, board and version |
| `GET /api/v1/settings` | Every setting, grouped by domain, with its value |
| `GET /api/v1/settings/{domain}/{name}` | One setting |
| `PUT /api/v1/settings/{domain}/{name}` | Change it: `{"value": "…"}`, always a string. Answers with the setting as saved |
| `GET /api/v1/entities` | Every entity: id, kind and details such as its name and unit |
| `GET /api/v1/states` | Every entity's current value |
| `GET /api/v1/events` | A WebSocket of values as they change |
| `GET /api/v1/actions` | The actions and their fields |
| `POST /api/v1/actions/{name}` | Run one: `{"args": {…}}`. Answers `{"answer": …}` |
| `POST /api/v1/buttons/{id}` | Press a button entity |
| `GET /api/v1/screen` | The screen as a JPEG |
| `GET /api/v1/logs`, `GET /api/v1/diagnostics` | The **Log** and **Diagnostics** downloads |

The domain and name are the ones `GET /api/v1/settings` lists, like `screen` and `backlight`.
Values are written the way it shows them: `on` or `off` for a switch, a number as text, and a
choice's id rather than its label.

To put a message on the screen:

```sh
curl -k -u :PASSWORD -X POST https://192.168.1.50/api/v1/actions/show_message \
  -d '{"args": {"title": "Laundry", "body": "The dryer is done", "seconds": 30}}'
```

<Aside type="caution">
Anyone with the admin password can change every setting, call the display and run its actions.
Keep the password to people you'd hand the display itself.
</Aside>
